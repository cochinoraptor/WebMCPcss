# A11y-MCP (v1.0.0)

Auditoría de accesibilidad **para agentes y personas**: los mismos problemas
que impiden a un lector de pantalla entender una página (botones sin nombre,
campos sin etiqueta, imágenes sin `alt`) impiden a un agente IA operarla.
A11y-MCP audita una URL con reglas WCAG 2.2 AA, propone correcciones en forma
de `.webmcp.css` (`webmcp-accessibility`) y un script que las aplica, y se
integra en CI.

- Código: `src/a11y/` (`rules.ts`, `index.ts`)
- CLI: `webmcpcss a11y audit | fix`
- Ejemplo: [`examples/v1/output/a11y/webmcp-a11y.yml`](../examples/v1/output/a11y/webmcp-a11y.yml)

## Reglas

| Regla                    | WCAG          | Impacto                                    | Corrección propuesta                            |
| ------------------------ | ------------- | ------------------------------------------ | ----------------------------------------------- |
| `html-has-lang`          | 3.1.1         | serious                                    | `lang` inferido del contenido                   |
| `document-title`         | 2.4.2         | serious                                    | —                                               |
| `meta-viewport-scalable` | 1.4.4         | serious                                    | `content="width=device-width, initial-scale=1"` |
| `image-alt`              | 1.1.1         | critical                                   | `alt` derivado del nombre de archivo            |
| `button-name`            | 4.1.2         | critical                                   | `aria-label` desde `title`/icono                |
| `link-name`              | 2.4.4         | serious / moderate (texto genérico «aquí») | `aria-label` desde `title`/`href`               |
| `label`                  | 1.3.1 / 3.3.2 | critical                                   | `aria-label` desde `placeholder`/`name`         |
| `heading-order`          | 1.3.1         | moderate                                   | —                                               |
| `landmark-one-main`      | 1.3.1         | moderate                                   | —                                               |
| `duplicate-id`           | 4.1.1         | serious                                    | —                                               |
| `tabindex-positive`      | 2.4.3         | serious                                    | `tabindex="0"`                                  |
| `aria-valid-role`        | 4.1.2         | serious                                    | —                                               |
| `iframe-title`           | 4.1.2         | serious                                    | `title` desde `src`                             |
| `autoplay-media`         | 1.4.2         | moderate                                   | —                                               |
| `target-size`            | 2.5.8         | minor                                      | — (requiere layout real; se omite en jsdom)     |
| `color-contrast`         | 1.4.3         | serious                                    | — (colores computados en el navegador)          |

Los elementos ocultos (`hidden`, `aria-hidden`, `display:none`) se ignoran;
`alt=""` y `role="presentation"` se consideran decorativos.

## CLI

```bash
# Auditar (URL o archivo HTML local)
webmcpcss a11y audit --url https://tienda.test
webmcpcss a11y audit --url https://tienda.test --min-score 85 --fail-on critical --json > a11y.json
webmcpcss a11y audit --url https://tienda.test --ci        # escribe .github/workflows/webmcp-a11y.yml

# Corregir de forma declarativa
webmcpcss a11y fix --url https://tienda.test -o a11y.webmcp.css --script a11y-fix.js
```

Salida de `audit`: puntuación 0-100 (`summarizeAudit`), problemas por impacto
(`critical|serious|moderate|minor`) y por regla, y el selector exacto de cada
elemento afectado. El código de salida respeta `--min-score` y `--fail-on`
(`passesThresholds`), por lo que funciona como puerta de calidad en CI.

### El `.webmcp.css` de correcciones

```css
/* webmcpcss a11y fix — https://tienda.test · puntuación 62/100 · 9 problemas */
img[src='/img/logo-tienda.png'] {
  webmcp-accessibility: 'alt: logo tienda';
  webmcp-a11y-rule: 'image-alt';
  webmcp-a11y-impact: 'critical';
}
input[name='email'] {
  webmcp-accessibility: 'aria-label: Email';
  webmcp-a11y-rule: 'label';
  webmcp-a11y-impact: 'critical';
}
```

`buildA11yFixScript(toolMap)` genera el script que aplica esos atributos en la
página (`window.__WEBMCP_A11Y__.applied`): añade `alt`/`aria-label`/`title`
solo cuando faltan y reemplaza `tabindex`/`lang`/`content` incorrectos. Puede
inyectarse con el proxy de Retro-WebMCP, con `webmcpcss inject` o como
snippet en el sitio.

## Integración en CI

`buildA11yWorkflow({ urls, minScore, failOnCritical })` genera un workflow de
GitHub Actions que audita cada URL en cada `pull_request` y sube los informes
JSON como artefacto. Ejemplo generado en `examples/v1/output/a11y/`.

## API

```ts
import { a11y } from 'webmcpcss';

const result = await a11y.auditPage(page); // Puppeteer
const result2 = a11y.auditDocumentInPage(document); // cualquier DOM (jsdom en tests)
const summary = a11y.summarizeAudit(result); // score, byImpact, byRule
const css = a11y.buildA11yCss(summary);
const script = a11y.buildA11yFixScript(parseWebMCP(css));
const gate = a11y.passesThresholds(summary, 85, 'critical'); // { ok, reasons }
```
